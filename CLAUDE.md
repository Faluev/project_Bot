# Project Instructions

## General Rules

* Read and understand the existing project structure before making changes.
* Follow the existing architecture, coding style, naming conventions, formatting and patterns.
* Make the smallest reasonable changes required to complete the task.
* Do not rewrite or refactor unrelated code.
* Do not create unnecessary files.
* Do not modify configuration files unless the task requires it.
* Do not add unnecessary comments or documentation.
* Preserve existing comments unless they are incorrect or directly affected by the change.

## Code Quality

* Write clean, maintainable, production-quality code.
* Reuse existing functions, components and utilities when appropriate.
* Avoid duplicated logic.
* Do not introduce unnecessary dependencies.
* Handle errors appropriately.
* Follow the conventions already established in the repository.
* Before finishing a task, review the changes for obvious bugs and unintended modifications.

## AI Attribution

* Do not add references to Claude, Anthropic, AI, artificial intelligence or AI-generated code anywhere in the project unless explicitly requested.
* Do not add watermarks, signatures, credits or other markers identifying AI involvement.
* Do not add AI-related comments to source code.
* Do not add `Generated by Claude`, `Generated by AI` or similar text anywhere in the repository.
* Do not add `Co-authored-by: Claude` or any other AI co-author attribution to Git commits.
* Do not change or fabricate existing human authorship information.
* Keep the project clean and professional without unnecessary attribution or signatures.

## Git

* Before creating a commit, inspect `git diff` and `git status`.
* Never commit unrelated changes.
* Never commit secrets, API keys, passwords, tokens or `.env` files containing sensitive credentials.
* Use concise, professional commit messages that describe the actual change.
* Do not mention Claude, Anthropic or AI in commit messages.
* Do not use `git push --force` unless explicitly requested.
* Do not delete branches or perform destructive Git operations unless explicitly requested.
* Before pushing changes to a remote repository, make sure the changes are intentional.

## Testing

* Run the relevant tests after making changes whenever possible.
* If the project has linting, formatting or type checking, run the relevant checks.
* If tests fail, investigate and fix the issue when it is within the scope of the requested task.
* Do not hide or ignore test failures.
* Report what was tested and whether it passed.

## Communication

* Be concise and direct.
* Before making substantial changes, explain briefly what you intend to change.
* After completing a task, summarize:

  1. What was changed.
  2. What was tested.
  3. Any remaining issues or things that require attention.
* Do not add unnecessary explanations.

## Important

When working on this repository, prioritize the project's existing conventions over personal preferences.

Do not make unrelated improvements unless explicitly requested.
